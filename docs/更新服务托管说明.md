# 稽古 · 更新服务托管说明（给开发者）

稽古有两条独立的更新通道，都用**静态文件托管**，不需要任何服务器程序、数据库或后端代码。

---

## 一、放在哪里

把 `dist\稽古\` 里的这些文件上传到一个能通过 HTTPS 直链访问的位置
（GitHub Raw、阿里云 OSS、腾讯云 COS、Nginx 静态目录、内网共享目录都行）：

```
<你的托管根目录>/
├─ app_version.json          ← 程序本体版本清单（小文件，每次发版都改）
├─ data_version.json         ← 史料数据版本清单（小文件，史料有变动时改）
├─ 稽古-安装包.exe            ← 程序本体安装包（发新版时上传，文件名可自定义，见下）
└─ corpus.json               ← 全量史料（史料更新时上传）
```

用户端默认读取地址：`https://raw.githubusercontent.com/alephpi/24histories-data/main`

**改地址的两种方式（都不需要用户操作安装步骤）**：

1. 分发时改 `update_base.txt`（与 exe 同目录，一行地址即可）：
   ```
   https://your-domain.com/jigu
   ```
2. 或用环境变量临时覆盖（调试用）：`JIGU_UPDATE_BASE=https://your-domain.com/jigu`

> 代码内**没有任何绝对路径**，一切以 `AppDomain.CurrentDomain.BaseDirectory` 为基准，
> 所以程序装在 `C:\Program Files\稽古`、`D:\软件\稽古` 还是 U 盘上都能正常找到自己的文件。

---

## 二、程序本体更新（app_version.json）

每次发布新版本，**只需替换这一个文件**：

```json
{
  "version": "1.7.0",
  "url": "https://your-domain.com/jigu/稽古-安装包.exe",
  "sha256": "安装包文件的 SHA-256（小写十六进制）",
  "notes": "本次新增：\n· 全量史料外置与倒排索引\n· 修复长时间运行的内存问题",
  "mandatory": false
}
```

| 字段 | 说明 |
| --- | --- |
| `version` | 版本号，按 `主.次.修订` 比较。**必须大于用户本地版本**才会提示 |
| `url` | 新安装包的直链。支持 `https://`、`http://` 与 `file://`（本地/共享目录） |
| `sha256` | **强烈建议填写**。程序会先校验再替换，防止下载被篡改或下载不完整；留空则跳过校验 |
| `notes` | 更新说明，会显示在弹窗里（用 `\n` 换行） |
| `mandatory` | 预留字段；当前版本仍会询问用户，不强制 |

**取 SHA-256（Windows 自带，无需装工具）**：

```powershell
Get-FileHash .\稽古-安装包.exe -Algorithm SHA256
```

**用户侧会发生什么**：程序启动 → 后台静默检查 → 发现新版本 → 弹窗
「发现新版本 v1.7.0，本次更新内容：…，是否现在更新？」→ 用户点「是」→
自动下载 → 校验 SHA-256 → 启动替换助手 → 覆盖旧文件 → 自动重启。全程不需要用户动手。

## 三、史料数据更新（data_version.json + corpus.json）

`data_version.json` 由 `build.ps1` 自动生成，形如：

```json
{
  "version": "0.1.0",
  "generated_at": "2026-09-24T00:00:00Z",
  "source_url": "https://github.com/alephpi/24histories-simplified-chinese",
  "books": { "corpus": "<corpus.json 的 SHA-256>" },
  "files": {
    "labels.json":    "<labels.json 的 SHA-256>",
    "stopwords.json": "<stopwords.json 的 SHA-256>"
  },
  "paths": {
    "corpus": "corpus.json",
    "labels.json": "labels.json",
    "stopwords.json": "stopwords.json"
  }
}
```

* `books` 里每一项是「史料名 → 该文件 SHA-256」，下载后**按 book 合并**进本地语料；
* `files` 里每一项是**整体替换的平文件**（不合并，下载后原样覆盖），目前是情境标签表
  `labels.json` 与查询停用词表 `stopwords.json`。这两张表是检索质量的主要可迭代资产，
  改它们不必重新编译 exe，所以单独放在这里；
* `paths` 是「史料名／文件名 → 相对路径」，程序按这个路径下载；
* 想按史书分文件下发就写多条，例如：

```json
{
  "version": "2.1.0",
  "books": {
    "corpus":    "<corpus.json 的哈希>",
    "史记补遗":   "<shiji-extra.json 的哈希>"
  },
  "paths": {
    "corpus":    "corpus.json",
    "史记补遗":   "books/shiji-extra.json"
  }
}
```

新增的史料文件格式（与现有语料一致）：

```json
{
  "book": "史记补遗",
  "items": [
    {
      "chapter": "项羽本纪",
      "title": "陈平反间，范增去楚",
      "original": "……原文……",
      "translation": "……白话译文……",
      "figures": ["项羽", "范增"],
      "decision": "……关键决策……",
      "outcome": "……最终结果……",
      "themes": ["将帅不和", "内部分裂"]
    }
  ]
}
```

**用户侧会发生什么**：程序启动 → 静默比对哈希 → 只下载变化的文件 → 校验
SHA-256 与 JSON 合法性 → 按 `book` 合并进本地 `corpus.json` → 重建倒排索引 →
界面上自动刷新。**失败一律静默降级**，继续用本地旧数据，绝不弹错误框。

## 四、手动触发与自测（可选）

程序内置了几个命令行参数，方便你发版前自测：

| 命令 | 作用 |
| --- | --- |
| `稽古.exe --selfcheck 报告.txt` | 校验界面资源 / 语料加载 / C# 检索 Top3 / 更新清单 |
| `稽古.exe --test-update <地址>` | 走完「检查→下载→校验→解压替换」全流程并输出报告（不弹窗） |
| `稽古-安装包.exe /silent /dir=<目录>` | 静默安装到指定目录（批量部署用） |
| `稽古-安装包.exe --extract-to <目录>` | 把安装包内容解开到指定目录（热替换内部使用） |
| `稽古-卸载.exe /uninstall /silent` | 静默卸载 |

**离线自测更新链路**：把 `dist\稽古` 复制一份，伪造一个"远端"目录放上
`app_version.json`、`data_version.json`、`corpus.json`、安装包，然后：

```powershell
$env:JIGU_UPDATE_BASE = "file:///D:/test-remote"
.\稽古.exe --test-update file:///D:/test-remote
```

报告里应出现 `RESULT: UPDATE SIMULATION OK (0 fails)`。

## 五、发版检查清单

- [ ] 改 `src/Update.cs` 里的 `AppVer.Number`（或让构建脚本注入）
- [ ] 用 `build.ps1` 重新构建，得到新的 `稽古-安装包.exe`
- [ ] `Get-FileHash` 取安装包 SHA-256
- [ ] 更新并上传 `app_version.json`（版本号 + 下载直链 + 哈希 + 更新说明）
- [ ] 若史料有变动：上传新的 `corpus.json`，用构建生成的 `data_version.json` 覆盖远端同名文件
- [ ] 在一台旧版本机器上启动，确认弹窗出现、点击后能自动更新并重启
